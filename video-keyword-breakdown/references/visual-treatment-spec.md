# 视觉处理规格（tier1 / tier3 的呈现形式）

> 定 tier1 和 tier3 的呈现形式时读这份。tier 的定义在 `keyword-taxonomy.md`，这份管的是**定完级之后写什么规格给下游**。
>
> 来源：吸收自 `chatcut-hyperframes-auto-editor` / `video-edit` 的 HUD 信息层做法，按本技能"只出方案不执行"的边界重写。

**这份文件解决一个具体问题**：以前 tier1 只写"独立大字弹出"，下游拿到这四个字只能自由发挥，每次做出来的东西都不一样。这里给出**有限的形式清单和必填规格**，让"强调"变成可复核的参数。

---

## 一、默认视觉语言

- **单强调色**：全片只用一个强调色（配一个警示色备用）。强调色出现在标题里的一个关键词、细发光线、图标描边上。**不要每一屏换颜色。**
- **等宽英文小标（kicker）**：大标题上方一行小号大写英文（可带中文），如 `MOVE 01 · DISTRIBUTION`、`SIGNAL 03 · 平台风控`。它承担分节和节奏感，不承担信息。
- **细发光线**：竖向刻度 + 下划线，只用一像素级细线，不用粗色块。
- **大字中文标题**：通常两行，其中一个关键词上强调色。
- **留白**：信息可以多，但必须有层级和短标签，不许整段文字堆上屏。

## 二、tier1 的六种呈现形式（从这里选，不要自由发挥）

**不要把每一条信息都塞进一个圆角玻璃卡。** 卡片留给真实截图、来源材料和 CTA。

| 形式 | 长什么样 | 什么时候用 |
|---|---|---|
| `holo_title` | kicker + 细发光下划线 + 大字中文标题 + 可选副标 | 一个观点、一节的开场，最常用 |
| `signal_rows` | 错落的几行，每行只有左侧竖线 + 下划线 + 半透明渐变 + 短标签 | 3-6 条并列要点，**替代列表卡** |
| `icon_dock` | 2-5 个圆形描边图标横排 | 角色、产品、平台、动作的并列 |
| `mini_panel` | 小块证明或公式模块 | 一个算式、一个对比、一个小结论 |
| `data_strip` | 细线 + 彩色数字的紧凑数据条 | 数字、指标、金额，不用大表格 |
| `source_shot` | 真实截图放进轻量描边框，带极轻微位移 | **证明用，不是装饰用** |

写进 `keywords_timeline.json` 的 tier1 条目必须包含 `visual_form` 字段，值取自上表。

**默认要避开的样子：**

- 一个大圆角矩形装下所有信息
- 同一侧竖着堆多张玻璃卡
- 卡片一进场就把所有行、标签、例子全亮出来
- 什么都不说明的科幻装饰

## 三、逐行揭示（最重要的一条定时规则）

**容器可以早进，内容不许早出。**

一个 `holo_title` 或 `signal_rows` 可以在段落开始时进场，但**它内部的每一行都是独立的定时资产**，各自在对应的口播时间点才揭示。

- ✅ 口播说到 A 时揭示 A 行，说到 B 时揭示 B 行
- ❌ 容器进场时把 A/B/C 全亮出来
- ❌ 把未来的内容用半透明"预告"出来但字还能读清——要么藏住，要么别放

所以 tier1 条目里的 `rows` 必须每行带自己的 `start`，不是整块一个时间。

**一段口播有 5-6 条内部主张时**：用一个大标题 + 逐行揭示，不要压成一段密集文字。

## 四、左主右证（16:9 人物居中时的分屏）

| 区域 | 放什么 | 约束 |
|---|---|---|
| 左侧 | 主信息层：当前这个观点 | 同一时间只放一个主槽位 |
| 右侧 | 证明/来源：截图、素材卡 | 最多两条竖向带 |
| 下方中央 | 字幕带 | **原片已有字幕时，这一带一律不可用** |
| 人脸区域 | — | 任何重要叠加都不许压 |

- **不许两侧同时同等密集。** 左边是讲，右边是证。
- **靠构造避让，不靠图层压盖**：两个元素会抢同一条带时，把它们排成先后，不要叠在一起。
- 新素材会盖住旧文字时，要么换空槽位，要么先把旧的淡出。
- 旧素材只在"还能读清 + 占独立槽位"时才允许留着。
- **左上角不要重复**：已经有大标题带了节号，就不要再挂一个常驻的小角标写同一个号。

竖屏 9:16 时把"左主右证"改成"上主下证"，右侧带改为主体下方的一条证明带，其余规则不变。

## 五、数字和单位必须跟口播一字不差

这是最容易出的硬错，且一旦出错整条视频的可信度就没了。

- 口播说"月入十万"，屏幕就必须是月度口径；说"去年进账一百万"，就必须是年度口径。**不许混用。**
- tier1 里凡是数字类条目，必须同时记录 `value`（数值）和 `unit_spoken`（口播里说的口径原文：月/年/一次性/MRR/ARR/总额）。
- 数字动画（count-up）只能在口播说出那个数之后开始，不能提前跑。

## 六、tier3 素材的额外约束

- 产品截图 / 来源截图**不早于**该产品或该来源被口播点名的时间出现。
- 同一槽位的下一张截图进场前，上一张必须先退场或让位。
- 截图是证明，不是装饰。一张截图如果不能用口播里的一句话解释它为什么在这儿，就从清单里去掉。
- 优先真实截图、真实界面、真实图表；生成图只在确实提升相关性时用，且必须在 `material_inserts.json` 里标注 `ai_generatable` 和"非真实界面"。

## 七、写进方案包时的必填字段

tier1 条目在原有字段之外，增加：

```
visual_form        六种形式之一
kicker             等宽英文小标文案（可为空）
accent_target      强调色落在标题里的哪个词
rows[]             逐行揭示时，每行的 text 和 start
value / unit_spoken  数字类条目必填
slot               left_main / right_proof / lower_third
```

tier3 条目增加：

```
slot               right_proof（默认）
earliest_start     不得早于的口播点名时间
exit_before        同槽位下一张素材的进场时间
```

**本技能只写这些规格，不生成任何动画、不渲染任何画面。** 规格写完仍然停在 `awaiting_human_confirmation`。
